# 03 数据库设计

## 1. 通用约定

- PostgreSQL；主键 UUID，由应用生成。所有私密资源带 `user_id`。
- 时间点使用 `timestamptz`，连接时区 UTC；自然日期使用 `date`，IANA 时区另存。`timestamptz` 不保留原始时区名称，设计依据见 [PostgreSQL 日期时间类型](https://www.postgresql.org/docs/current/datatype-datetime.html)。
- `created_at/updated_at` 为必填时间点；状态先采用字符串加 CHECK，方便迁移。
- 表中的 `?` 表示可空。字段默认不可空，数组默认空数组，JSON 默认值由应用创建，不共享可变对象。
- 涉及用户私密数据的 FK 采用级联删除；发布活动采用归档与版本化，不直接删除被引用内容。
- 输入的长度、JSON 形状由 Pydantic 校验；数据库再次约束评分、版本、状态、唯一键与关系。

## 2. 用户、会话与授权

### users

| 字段 | 类型／约束 |
|---|---|
| id | uuid PK |
| email | varchar(254)，规范化后 UNIQUE |
| password_hash | text，Argon2id 哈希 |
| nickname | varchar(30)? |
| timezone | varchar(64)，默认 Asia/Shanghai |
| adult_confirmed_at | timestamptz |
| terms_version / privacy_version | varchar(32) |
| status | active / deleting |
| data_version | bigint，默认 1，CHECK >0 |
| consent_version | bigint，默认 1，CHECK >0 |
| ai_enabled | boolean，默认 false |
| created_at / updated_at | timestamptz |

`data_version` 在影响统计或回顾的输入变化时递增；`consent_version` 在授权状态改变时递增。Worker 写回前重新校验，防止删除和撤权后结果复活。

### sessions

| 字段 | 类型／约束 |
|---|---|
| id | uuid PK |
| token_hash | char(64)，UNIQUE，不能保存 Cookie 明文 |
| csrf_token | varchar(128)，随机同步器 token |
| user_id | uuid? FK users ON DELETE CASCADE；null 为匿名会话 |
| expires_at / created_at | timestamptz |

索引 `expires_at` 用于定时清理。用户 token 和 CSRF token 分别随机生成；读取 session 的响应不可缓存。

### consent_events

字段：`id uuid PK, user_id uuid FK, action granted/revoked, policy_version varchar(32), provider_key varchar(64), purpose varchar(64), occurred_at timestamptz`。服务端填时间，保留本人可导出的授权历史。注销时级联删除，首版不额外保留可识别用户审计副本。

## 3. 日记与分析

### journals

| 字段 | 类型／约束 |
|---|---|
| id / user_id | uuid PK / uuid FK users |
| client_request_id | uuid，用户内唯一 |
| request_fingerprint | char(64)，首次创建请求的规范化摘要 |
| mood_score | smallint CHECK BETWEEN 1 AND 5 |
| emotions | jsonb，数组 1～5 项，条目 `{code,label}` |
| body | text，默认空，CHECK char_length<=10000 |
| event_tags | jsonb，数组最多 5 项 |
| occurred_at | timestamptz |
| version | integer，默认 1，CHECK >0 |
| created_at / updated_at | timestamptz |

索引：`(user_id, occurred_at DESC, id DESC)`；唯一 `(user_id, client_request_id)`；`event_tags` 可用 GIN 索引支持包含查询。自定义标签过滤同时匹配 code 与 label。

数据库不保存 local_date：按用户当前时区动态分组。API 不接受客户端 user_id、version 初始值或分析字段。

### entry_analyses

字段：`id uuid PK, user_id uuid FK, journal_id uuid UNIQUE FK journals ON DELETE CASCADE, journal_version int, consent_version bigint, summary text, reflection_question text?, prompt_version varchar(32), provider_key varchar(64), model_key varchar(128), created_at timestamptz`。

通过组合唯一键与 FK 保证 journal owner 一致：journals 增加 `UNIQUE(id,user_id)`，分析的 `(journal_id,user_id)` 引用它。其它带 owner 的日记引用采用同一规则。

### analysis_factors

字段：`id uuid PK, analysis_id uuid FK entry_analyses ON DELETE CASCADE, label varchar(100), hypothesis text, evidence_quote text, review_status varchar(16), user_text varchar(300)?, updated_at timestamptz`。

`review_status` 限定 `unreviewed/matches/partial/rejected`。一个分析最多 3 条线索，由服务端限制；`evidence_quote` 必须是该版本 body 的精确子串。分析不保存原始模型输出。

## 4. 内容与活动

### activities

字段：`id uuid PK, slug varchar(80) UNIQUE, version int, title varchar(100), type varchar(20), duration_minutes smallint, scenes jsonb, steps jsonb, audio_asset_key text?, suitability_note text, source_name text, source_url text?, license_note text, reviewer text?, reviewed_at timestamptz?, review_due_at timestamptz?, status draft/published/archived, created_at/updated_at timestamptz`。

约束：时长 1～60；steps 至少一项，由输入 schema 校验；状态 published 时必须有审核人、审核时间、复核期限、来源和授权说明。审核到期的活动不参与推荐。外部音频资源只允许已审核域名或私有对象存储 key，不能由模型指定 URL。

slug 不变时更新未发布草稿；已发布内容变更生成新活动 ID，并将旧版本归档。旧活动会话仍可显示历史快照，但不能新开已归档活动。

### care_sessions

| 字段 | 类型／约束 |
|---|---|
| id / user_id | uuid PK / uuid FK |
| activity_id | uuid FK activities，限制删除 |
| journal_id | uuid?，同 owner FK，删除日记时清空该关联 |
| client_request_id / request_fingerprint | uuid / char(64)，用户内请求 ID 唯一 |
| activity_snapshot | jsonb，仅存公开标题、步骤、版本、类型，不存日记 |
| status | running / paused / completed / stopped |
| version | int，默认 1 |
| elapsed_seconds | int，默认 0，CHECK >=0 |
| started_at / updated_at | timestamptz |
| ended_at | timestamptz? |
| before_score / after_score | smallint?，非空时 1～5 |
| helpfulness | helpful / neutral / not_suitable 或 null |
| feedback_note | varchar(500)? |

索引 `(user_id,started_at DESC)`，唯一 `(user_id,client_request_id)`。日记关联 FK 实现时使用 owner 组合校验，但删除只把 `journal_id` 清空，不能误清 user_id；可在删除事务显式更新关联，再删除日记。

## 5. 持久化任务与周回顾

### jobs

字段：`id uuid PK, user_id uuid FK, kind entry_analysis/weekly_review, resource_id uuid?, input_meta jsonb, dedupe_key char(64), status queued/running/succeeded/failed/cancelled, attempt int, max_attempts int DEFAULT 2, available_at timestamptz, lease_until timestamptz?, lease_token uuid?, result_id uuid?, error_code varchar(64)?, created_at/updated_at timestamptz`。

`input_meta` 仅保存 journal_version、consent_version 或日期、timezone、data_version、模板版本，不放正文和证据。`resource_id/result_id` 是按 kind 解释的逻辑引用，服务层必须做存在性与 owner 校验。

索引 `(status,available_at,created_at)`；对 `status IN ('queued','running')` 建 `(user_id,kind,dedupe_key)` 部分唯一索引。已完成结果通过资源当前版本判断复用，不依赖终态任务永久占据去重键。

### weekly_reviews

字段：`id uuid PK, user_id uuid FK, start_date date, end_date date, timezone varchar(64), source_data_version bigint, consent_version bigint, input_fingerprint char(64), statistics jsonb, insight_eligible boolean, narrative text?, observations jsonb, ai_status disabled/insufficient/succeeded/failed/safety_blocked, prompt_version varchar(32), created_at timestamptz`。

约束：end_date=start_date+6；唯一 `(user_id,input_fingerprint)`。observations 中的证据只能引用仍存在的本人日记 ID 或统计字段路径；保存前检查。

### support_resources

字段：`id uuid PK, region_code varchar(16), title text, description text, contact_text text?, url text?, source_url text, verified_by text, verified_at timestamptz, review_due_at timestamptz, status draft/published/archived`。

仅公开审核后且未到期的资源。不在本次文档中填未经核验的电话号码或声称资源已审核。

### rate_limit_counters 与 ai_usage_reservations

首版限额使用 PostgreSQL 共享计数，不能采用各 API/worker 进程独立的内存计数器。

- `rate_limit_counters`：`bucket_key varchar(128), window_start timestamptz, count int, expires_at timestamptz`，前两项组合 PK；原子 UPSERT 递增。登录 IP 键使用独立用途 HMAC，不存原始 IP；用户限额键同样采用不可直接识别的摘要。计数到期删除。
- `ai_usage_reservations`：`id uuid PK, user_id uuid FK users ON DELETE CASCADE, job_id uuid?, attempt int, budget_date date, currency varchar(8), reserved_amount numeric(18,8), settled_amount numeric(18,8)?, input_tokens int?, output_tokens int?, status reserved/settled/released, created_at/updated_at timestamptz`，唯一 `(job_id,attempt)`。预算日统一 UTC，与用户日记自然日区分。
- 全局预算预留使用 PostgreSQL 事务级 advisory lock 按预算日串行核算，余额不足不调用；任务重试按 attempt 独立预留，计费总量包含重试。金额用 Decimal，不用浮点。
- reservation 保留 token、费用和内部 ID，不含正文；任务清理时 job_id 清空，用户注销级联删除。终态计费明细最多保留 30 天，可保留不可识别的日聚合总额以避免注销导致当日预算被释放。

## 6. 关键事务

### 保存与编辑

1. 锁定当前用户行，确认 active。
2. 创建按 client_request_id 去重；同 ID 同摘要返回原资源，同 ID 不同摘要返回 409。
3. 编辑限定 owner 和 version；成功时 version+1，删除旧分析及对应在途任务的写回资格。
4. users.data_version+1，删除该用户全部 weekly_reviews，取消在途 weekly_review。
5. 同一事务提交。创建后立即删除同样会清理缓存，不遗漏补记。

### 分析／回顾写回

模型调用完成后开始短事务，先锁用户，再检查 owner、active、授权版本、来源版本和 lease_token。失败则丢弃模型结果；符合才保存结果并将任务置 succeeded。回顾还必须匹配 source_data_version，避免模型工作期间输入改变。

任何分析或回顾被删除／失效时，同事务删除指向该结果的终态 job，取消对应在途 job；终态不改写为 cancelled。查询已删除任务返回 404，不留下 succeeded 指向不存在结果的悬空引用。

### 删除与撤权

- 删除日记：先置相关任务 cancelled 并清除 result_id，清空活动日记关联；级联删除分析，删除日记，递增 data_version，删除所有回顾并取消回顾任务。
- 撤权：同事务 ai_enabled=false、consent_version+1、data_version+1、写授权事件、取消 AI 任务、删除分析与回顾。取消后清除含结果 ID 的元数据。
- 注销：校验密码后，锁用户并将状态改为 deleting；本事务级联删除用户及全部私密记录，会话随之失效。公开活动与支持资源不删除。
- 用户数据变化与 worker 写回都按“用户行 → 日记／任务／结果”顺序加锁，降低死锁风险。

账号删除、日记删除与授权撤回在成功应答前，还需持久记录受限恢复清单，详见 09。该清单放在独立持久卷，不随应用主库恢复回滚，不对产品接口开放。

## 7. 迁移与数据准备

迁移顺序：用户会话授权 → 日记分析 → 内容活动 → 任务回顾 → 支持资源及索引。

所有变更使用 Alembic，不在生产使用 ORM create_all 替代迁移。应用与 worker 启动前单独运行迁移。测试使用 PostgreSQL，不能用 SQLite 代替涉及 JSONB、锁与时区的验证。

开发 seed 只创建虚构日记，内容未审核时保持 draft。正式发布前需完成 20～30 项真实内容审核；不能把 seed 的虚构 reviewer 当成审核证据。
