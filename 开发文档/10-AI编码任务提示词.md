# 10 AI 编码任务提示词

这些提示词用于后续逐任务生成代码，本轮文档交付不执行其中的开发或部署指令。使用前将任务 ID、目录和实际状态填入，不要一次要求工具完成全部项目。

## 1. 通用任务模板

```text
项目：心晴日记，技术栈 FastAPI + React + PostgreSQL。
先读取项目计划.md、开发文档/README.md 和本任务相关文档，检查现有代码与仓库 AGENTS.md。

当前任务：[Txx 名称]
对应需求：[Rxx]
允许修改：[目录或模块]
前置任务状态：[实际完成情况]
必须满足的行为：[含正常、空态、错误、权限和并发场景]
验收用例：[Cxx]

要求：
1. 依据已有 API 字段、状态和数据库设计实现，不能另起一套相近命名。
2. 先阅读现有工程再修改；不覆盖用户代码、不新增计划外功能。
3. 服务端从 session 获取 user_id，所有私有资源查询限制 owner；不信任客户端 user_id。
4. 日记保存不依赖模型；真实 AI 需开关和用户授权；无密钥使用关闭模式或明确的测试 fake。
5. 处理实际持久化、失败和取消，不能用硬编码成功、假播放或假 AI 结果冒充功能。
6. 仅为关键业务风险补充有意义测试，运行受影响检查并记录真实结果。
7. 协议或字段变更要同步文档；没有外部凭据或审核结果时明确待接入，不伪造。

完成后报告：修改文件、实现行为、实际验证命令/结果、剩余限制与下一依赖。
```

## 2. 阶段 A：工程与数据库（T02/T03）

```text
依据 02、03、09 创建前后端基础工程和 PostgreSQL 开发配置。
使用 Python 3.12、FastAPI、SQLAlchemy、Alembic；React + TypeScript + Vite。
创建目录、配置加载、统一错误、健康检查、路由入口、日志脱敏及数据库迁移。
建立 uv.lock 与 package-lock.json、.env.example、运行说明及忽略文件。
禁止真实密钥、默认生产密码、自动演示灌入；AI 默认关闭。
先提供可以运行的最小工程，再创建业务模型与迁移。
验收：从空库迁移成功，API health、前端构建、配置失败分支可验证。
```

## 3. 阶段 B：账号与会话（T04/T05）

```text
依据 03/04/05 实现不透明 Cookie Session、匿名 session/CSRF、注册登录退出、me 与 AI 授权。
注册与登录旋转会话，CSRF 覆盖包括 PUT 在内的全部写方法，生产 Cookie 安全配置。
实现用户授权版本递增及撤权清理的服务接口，前端内存保存 CSRF，处理刷新、401 与缓存清理。
用 C01～C04 验证真实权限，不只测试前端隐藏按钮。
首版不增加短信、第三方登录、邮件服务或 OAuth2 密码流。
```

## 4. 阶段 C：日记闭环（T06/T07）

```text
实现日记 CRUD、按日期/情绪/标签筛选、请求 ID 去重及 version 乐观锁。
表单支持正文留空、多情绪、自定义条目、补记、当前标签页草稿恢复。
保存不调用模型；后端不接受 client user_id；删除事务清理分析和回顾并清空活动关联。
前端处理重复点击、网络失败、409 冲突、删除确认和未保存离开。
执行 C05～C11；特别验证同请求并发只建一条记录。
```

## 5. 阶段 D：确定性回顾（T08/T09）

```text
依据 01/04/05 实现近 7/30 天统计、日历和趋势。
统一按用户 IANA 时区划分自然日；缺失日 mean_score=null，不插值为正常。
验证当日 1、5，次日 2 时 daily=3.0/2.0，区间 mean=2.7；多选百分比可超 100%。
图表提供文字表格，时区改变后失效缓存，不能由模型计算任何统计数值。
完成 C12～C14 及键盘/窄屏体验。
```

## 6. 阶段 E：任务与 AI（T11/T12/T13）

```text
依据 03/04/06 实现数据库任务队列、独立 worker、SKIP LOCKED 租约、续租和最多两次执行。
实现 entry_analysis 和 weekly_review 两种任务，禁止将 FastAPI 进程内后台任务当持久化队列。
提供延迟、超时、非法 JSON、错误证据、保护分支可配置的 fake provider，真实 provider 通过配置接入。
模型调用不持锁；写回校验 lease_token、user active、journal version/data_version、consent_version。
编辑、删除、撤权、注销和旧 worker 迟到响应不能写回。
前端显示实际任务状态，支持重试与取消，引用和用户纠正可见。
执行 C15～C21 和模型评估；不得打印真实正文、密钥或原始模型输出。
```

## 7. 阶段 F：活动与反馈（T10/T14）

```text
实现审核内容导入工具、活动列表详情、规则推荐、执行会话、暂停继续、终态与可选反馈。
未审核样例保持 draft，不能伪造 reviewer 或音频授权。
推荐先按审核期限、时间、场景和排除类型筛选，最多 3 条，无候选不放宽条件。
无模型或未授权时推荐仍可用，理由使用规则模板；音频不可用保留文字步骤。
状态机与 version 在后端验证，前端刷新不自动累计不确定的后台时长。
执行 C22～C24、C32；示例内容与实际审核资料分开说明。
```

## 8. 阶段 G：周回顾与数据控制（T15/T16）

```text
实现连续 7 天周回顾，至少 3 个记录日才允许跨日 AI 线索；未授权、模型失败均保留程序统计。
实现版本缓存、编辑/补记/纠正/反馈/时区改变后的失效，不能回写旧 data_version 结果。
实现本人数据 JSON 导出、授权撤回、密码确认注销及浏览器缓存清理。
删除覆盖主库衍生结果，备份与供应商保留边界按实际披露；恢复删除清单机制见 09。
执行 C25～C29，竞态测试用受控 barrier，不能用随机等待掩盖问题。
```

## 9. 阶段 H：交付验证（T17/T18）

```text
对照全部 P0 和 08 逐项检查现有实现，先列缺口并修复，不扩大范围。
运行静态检查、后端 PostgreSQL 集成测试、前端类型检查和构建、四条端到端流程。
准备同站部署、单次迁移、健康检查、worker 恢复、备份与恢复演练说明。
内容、安全及真实模型评估没有执行就写未执行，不能以 fake 模型测试替代真实服务验收。
生成含版本、命令、结果、缺陷与限制的验收报告和使用虚构数据的演示脚本。
禁止擅自发送外部消息、发布公网服务、填入未经核验求助号码或执行未经授权的破坏性恢复。
```

## 10. 故障修复模板

```text
问题：[用户可见行为与实际错误]
期望：[对应 Rxx / Cxx]
复现：[最小步骤、版本、环境；不包含真实私密日记或密钥]
先定位根因，再修改必要代码；保持既有接口与产品范围。
如涉及权限、数据丢失、竞态或统计，补充能证明修复的回归测试。
运行受影响验证，说明已确认结果与尚未验证项。
```
